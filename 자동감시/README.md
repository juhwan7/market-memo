# 자동 감시

`market-memo`에서 시간이 지나면 상태가 바뀌는 이벤트를 공식 자료 기준으로 감시하는 폴더입니다.

## 현재 구현 범위

첫 감시 대상은 **무신사 IPO**입니다.

현재 버전은 중간 단계를 기사로 추정하지 않고, 한국거래소 KIND의 `신규상장기업현황`에서 무신사가 실제로 확인되는지를 주기적으로 검사합니다.

```text
상장예비심사 진행
        ↓
(중간 단계는 AI가 최신 조사 시 별도 확인)
        ↓
KRX KIND 신규상장기업현황에서 무신사 확인
        ↓
신규상장 완료로 자동 변경
        ↓
자동 PR 생성
```

## 왜 바로 main을 수정하지 않나

외부 사이트의 HTML 구조 변경이나 일시적인 오류로 잘못 감지할 가능성을 줄이기 위해 자동화는 `main`을 직접 수정하지 않습니다.

상태가 바뀌면 `auto/ipo-status-update` 브랜치에 변경을 만들고 Pull Request를 생성합니다. 사용자가 PR 내용을 확인한 뒤 병합하는 구조입니다.

## 자동으로 바뀌는 내용

무신사 신규상장이 공식 확인되면 다음을 변경합니다.

- `자동감시/상태/무신사-ipo.json`
- `종목분석/비상장기업/무신사-IPO.md`의 현재 상태
- `최근-업데이트.md`
- 루트 `README.md`
- KIND 페이지에서 6자리 종목코드를 자동 추출할 수 있으면 `종목분석/한국주식/종목코드-무신사.md` 전환 초안 생성

## 실패 시 원칙

- KIND 접속 실패 → 상태 변경 안 함
- HTML 파싱 실패 → 상태 변경 안 함
- 무신사를 찾지 못함 → 기존 상태 유지
- 일반 기사에서 상장 보도 → 자동 상태 변경 안 함
- KRX KIND 신규상장기업현황에서 직접 확인 → 변경 후보 생성

즉 **확인 실패를 상태 변화로 해석하지 않는 fail-closed 방식**입니다.

## 실행 주기

GitHub Actions가 평일 한국시간 기준 대략 오전 9시 30분과 오후 5시 30분에 확인합니다. `workflow_dispatch`를 통해 GitHub Actions 화면에서 수동 실행도 할 수 있습니다.

## 감시 대상 추가

새 대상은 루트 [`감시대상.yaml`](../감시대상.yaml)에 추가합니다.

향후 확장 후보:

- 다른 IPO 기업
- M&A 완료 여부
- 지수 편입·편출
- 임상 주요 단계
- 대형 수주·계약 상태
- 정부 정책 시행 여부

단, 자동화로 문서의 현재 상태를 바꾸는 조건은 가능한 한 거래소·공시·정부·기업 공식 발표 같은 1차 자료에 한정합니다.
