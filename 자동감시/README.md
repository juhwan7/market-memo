# 자동 감시

`market-memo`에서 시간이 지나며 상태가 바뀌는 이벤트를 최신 원문 기준으로 추적하는 폴더입니다.

자동감시는 이제 **두 가지 방식**으로 나눕니다.

```text
정형 데이터·명확한 상태
→ GitHub Actions 결정형 감시

정책·외교·기업 이벤트처럼
문맥을 읽어야 하는 변화
→ ChatGPT AI 상태감시
```

---

## 1. 결정형 GitHub Actions 감시

첫 구현 대상은 **무신사 IPO**입니다.

한국거래소 KIND `신규상장기업현황`처럼 상태를 기계적으로 판별할 수 있는 공식 데이터는 Python + GitHub Actions가 확인합니다.

```text
상장예비심사 진행
        ↓
KRX KIND 신규상장기업현황 확인
        ↓
무신사 신규상장 공식 확인
        ↓
신규상장 완료 변경 후보
        ↓
자동 PR
```

기사 문구로 중간 단계를 추정하지 않습니다.

---

## 2. ChatGPT AI 상태감시

정책·지정학·기업 사업진행처럼 단순 키워드로 상태를 확정하기 어려운 자료는 `감시대상.yaml`의 `watch_mode: ai_state_watch` 대상으로 관리합니다.

현재 등록 대상:

- 트럼프 5,000달러 `Trump Dividend`
- Tesla Cybercab / Robotaxi
- 중국의 Trump–Kim Jong Un 회동 중재 가능성

AI 상태감시는 각 대상의:

- 기준 문서
- 상태 JSON
- 이전 조사 내용
- 공식 원문
- 신뢰도 높은 최신 보도

를 먼저 읽고 **실제로 의미 있는 변화가 있을 때만** 갱신합니다.

---

## 3. 사용자가 최신 자료만 순서대로 읽을 수 있게 만드는 규칙

상태가 바뀌면 기존 내용을 그냥 지우지 않습니다.

```text
현재 기준 문서 v1
        ↓
새로운 공식 발표·의미 있는 변화 감지
        ↓
기존 v1 전체 내용을
자동감시/이력/<대상>/<날짜>-이전-버전.md 로 보존
        ↓
현재 기준 문서를 v2로 갱신
        ↓
문서 상단에
- 이전 버전 링크
- 이번에 달라진 점
- 현재 단계
- 다음 확인사항
추가
        ↓
최근-업데이트.md + README 갱신
```

따라서 사용자는 최신 자료부터 읽고, 필요할 때만 `이전 버전` 링크로 과거 상태를 확인할 수 있습니다.

### 최신 문서 상단 예시

```markdown
## 이번 업데이트에서 달라진 점

- 이전 버전: [2026-09-10 기준](../../../자동감시/이력/.../2026-09-10-이전-버전.md)
- 이전 상태: 선거 공약
- 현재 상태: 법안 발의

### 새로 확인된 내용
- 법안번호 H.R. XXXX 공개
- 지급 대상 소득기준 발표
- 재원으로 관세수입 일부 사용 명시

### 그대로인 내용
- 실제 지급일은 아직 미확정
- 상원 통과 전
```

핵심은 **전체 설명을 매번 처음부터 새 문서로 만들지 않고, 기준 문서는 최신 상태로 유지하면서 과거 버전은 링크로 보존**하는 것입니다.

---

## 4. 상태 승격 규칙

### 공식 자료가 있는 경우

정부·거래소·법정공시·기업 IR·규제기관 같은 1차 자료가 새 단계를 명확히 확인하면 현재 상태를 승격할 수 있습니다.

예:

```text
Trump Dividend
공약
→ 백악관 구체안
→ 법안 발의
→ 하원 통과
→ 상원 통과
→ 대통령 서명
→ 지급 시행
```

```text
Tesla Cybercab
생산
→ 제한 운행
→ 규제 승인
→ 도시 확대
→ 대량 운행
→ 매출 본격 반영
```

### 기사만 있는 경우

신뢰도 높은 기사라도 공식 확인이 없으면:

- 새로운 관심 신호로는 기록 가능
- `현재 상태`를 확정 단계로 자동 승격하지 않음
- `보도 / 시장 기대 / 확인되지 않음` 라벨 유지

중국의 Trump–Kim 중재 가능성 자료가 현재 이 단계입니다.

---

## 5. 의미 있는 변화가 아니면 아무것도 하지 않는다

다음은 새 업데이트로 취급하지 않습니다.

- 같은 발언을 재인용한 기사
- 제목만 다른 재탕 기사
- 출처 없는 SNS 루머
- 기존 사실을 다시 설명한 보도
- 숫자나 상태가 실제로 바뀌지 않은 기사

즉 `no change → no commit`이 기본입니다.

---

## 6. 이전 버전 보존 규칙

AI 상태감시 대상이 실제로 갱신되기 직전 현재 기준 문서를 다음 경로에 복사합니다.

```text
자동감시/이력/<대상-id>/YYYY-MM-DD-HHMM-이전-버전.md
```

상태 JSON에는 최신 이력 파일 경로를 저장합니다.

과거 이력은 원칙적으로 삭제하지 않습니다.

---

## 7. 자동으로 함께 갱신할 파일

의미 있는 상태 변화가 있으면 같은 작업에서 다음을 확인합니다.

- 기준 분석 문서
- `자동감시/상태/<대상>.json`
- `자동감시/이력/<대상>/...`
- 관련 인덱스
- `최근-업데이트.md`
- 루트 `README.md`

이렇게 해야 GitHub 프로필의 `최근 업데이트된 자료`에서도 실제로 바뀐 기준 문서가 최신순으로 보입니다.

---

## 8. 감시 대상 등록

루트 [`감시대상.yaml`](../감시대상.yaml)에 추가합니다.

각 AI 감시 대상은 최소한 다음 정보를 갖습니다.

- `id`
- `document`
- `state_file`
- `history_dir`
- 1차 출처
- 보조 출처
- `meaningful_changes`

새로운 자료를 만들 때 상태가 계속 바뀔 주제라면 AI가 자동감시 대상에 넣을 가치가 있는지도 같이 판단합니다.

---

## 9. 실패 시 원칙

- 공식 사이트 접속 실패 → 기존 상태 유지
- 출처 간 내용 충돌 → 자동 확정 금지
- 기사 하나만 존재 → 공식 상태 승격 금지
- 문서의 기존 상태를 이해하지 못함 → 갱신 금지
- 변화가 불명확함 → 기존 상태 유지

즉 **확신이 없을수록 쓰지 않는 fail-closed 방식**을 유지합니다.

---

## 10. GitHub Actions 권한

무신사 같은 결정형 감시는 현재 자동 PR 방식입니다.

```yaml
permissions:
  contents: write
  pull-requests: write
```

필요한 범위보다 넓은 `write-all` 권한은 사용하지 않습니다.

AI 상태감시는 연결된 GitHub 권한 범위 안에서 기준 문서와 이력을 갱신합니다.
