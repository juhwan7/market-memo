# 자동감시 작업 규칙

이 폴더의 자동화는 시간이 지나며 상태가 바뀌는 이벤트를 확인합니다. 잘못된 자동 변경은 오래된 메모보다 더 위험하므로 일반 문서보다 보수적으로 수정합니다.

## 절대 원칙

1. 자동 상태 승격의 근거는 거래소·법정공시·정부·규제기관·기업 공식 발표 같은 1차 자료를 우선합니다.
2. 뉴스 기사·SNS·커뮤니티만으로 `현재 상태`를 확정 단계로 올리지 않습니다.
3. 공식 사이트 접속 실패·HTML 구조 변경·파싱 실패를 `상태 변화`로 해석하지 않습니다.
4. 확실하지 않으면 기존 상태를 유지합니다. 즉 fail-closed 방식입니다.
5. 상태가 바뀌어도 과거 진행 이력을 삭제하지 않습니다.
6. 의미 있는 변화가 없으면 문서·상태 파일·Git 커밋을 만들지 않습니다.

## 감시 방식 구분

### deterministic_github_action

KIND 신규상장 여부처럼 정형 데이터에서 기계적으로 판별 가능한 상태에 사용합니다.

- 현재 무신사 IPO가 해당
- 잘못된 감지 가능성을 줄이기 위해 자동 PR 방식 유지
- `main` 직접 수정 금지

### ai_state_watch

정책·외교·기업 사업 진행처럼 기존 문맥과 새로운 자료를 같이 읽어야 의미를 판단할 수 있는 대상에 사용합니다.

AI 상태감시는 반드시 다음 순서로 작업합니다.

```text
감시대상.yaml 확인
→ state_file 확인
→ 현재 기준 문서 전체 읽기
→ 최신 1차 자료 확인
→ 필요한 경우 신뢰도 높은 보조자료 교차검증
→ 기존 내용과 비교
→ 의미 있는 변화 여부 판정
```

의미 있는 변화가 있을 때만 갱신합니다.

## 이전 버전 보존 — AI 상태감시 필수

기준 문서를 수정하기 전에 현재 문서 전체를 먼저 보존합니다.

경로:

```text
자동감시/이력/<대상-id>/YYYY-MM-DD-HHMM-이전-버전.md
```

그 다음 최신 기준 문서 상단에 다음을 명시합니다.

1. 이전 버전 링크
2. 이전 상태
3. 현재 상태
4. 이번에 새로 확인된 내용
5. 기존과 달라진 점
6. 여전히 미확정인 내용
7. 다음 확인 이벤트

사용자는 최신 문서부터 읽고, 필요할 때만 이전 버전 링크를 따라갈 수 있어야 합니다.

## 상태 라벨

- `확정`
- `당사자 주장`
- `가능성 높음`
- `시장 기대`
- `추정`
- `확인되지 않음`

기사 보도가 새로 나왔더라도 공식 확인이 없으면 `확정`으로 올리지 않습니다.

## 보안

- API 키·토큰·비밀번호를 저장소에 직접 적지 않습니다.
- 인증이 필요한 기능은 GitHub Secrets 또는 연결된 서비스의 권한 시스템을 사용합니다.
- 외부 입력을 그대로 쉘 명령으로 실행하지 않습니다.
- 비신뢰 PR 코드에 높은 쓰기 권한을 주지 않습니다.
