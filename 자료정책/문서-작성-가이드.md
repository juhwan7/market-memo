# 문서 작성 가이드 — 이해 중심 심화 시장 메모

이 저장소의 문서는 단순한 기사 요약이 아니라, 읽고 나면 사건의 배경·원인·산업 구조·투자 의미까지 연결해서 이해할 수 있는 개인 시장 메모를 목표로 합니다.

핵심 원칙은 **상단은 빠르게, 본문은 깊게, 반복은 없이**입니다.

## 1. 기본 구조

일반적인 산업·종목·정책 분석은 아래 순서를 기본으로 합니다.

~~~text
3줄 핵심
→ 왜 중요한가
→ 먼저 쉽게 이해하면
→ 현재 무슨 일이 벌어졌나
→ 왜 이런 일이 생겼나
→ 산업·사업 구조 / 공급망 / 병목
→ 핵심 근거와 숫자
→ 반론·다른 가능성
→ 투자 관점 / 국내 기업에 미치는 의미
→ 시간순 흐름
→ 앞으로 확인할 지표
→ 핵심 결론
→ 기억할 한 문장
→ 출처
~~~

주제에 맞지 않는 섹션은 생략할 수 있습니다. 형식을 채우는 것이 목적이 아니라 독자가 논리를 이해하는 것이 목적입니다.

## 2. 3줄 핵심

문서 맨 위에서 다음 세 가지를 바로 알려줍니다.

1. 지금 무슨 일이 벌어졌는가
2. 왜 시장에서 중요한가
3. 무엇이 아직 불확실한가

가능하면 세 문장 또는 세 개의 짧은 bullet로 끝냅니다.

## 3. 왜 중요한가

단순히 '호재다', '악재다'라고 쓰지 않습니다.

사건이 실적이나 주가로 전달되는 경로를 설명합니다.

예:

~~~text
AI 데이터센터 증가
→ 24시간 안정적인 전력 수요 증가
→ 가스발전 프로젝트 증가
→ 가스터빈 주문 증가
→ 제조사 납기·가격·가동률 상승
~~~

독자는 이 부분을 읽고 뉴스가 왜 해당 산업과 기업에 연결되는지 이해할 수 있어야 합니다.

## 4. 먼저 쉽게 이해하면

전문지식이 없는 사람이 읽는다고 가정합니다.

- 산업이나 기술이 무엇인지
- 왜 필요한지
- 기존 방식과 무엇이 다른지

를 쉬운 말로 설명합니다.

단, 교과서식 정의를 길게 쓰지 않고 이번 사건을 이해하는 데 필요한 내용만 설명합니다.

## 5. 원인과 구조까지 들어간다

심화형 문서는 '무슨 일이 벌어졌다'에서 끝나지 않습니다.

가능하면 다음을 확인합니다.

- 수요가 왜 늘거나 줄었는가
- 공급은 왜 바로 따라가지 못하는가
- 핵심 병목은 무엇인가
- 누가 가격 결정력을 가지고 있는가
- 경쟁사의 증설과 진입은 어떻게 변하고 있는가
- 단기 호황이 장기적으로 어떤 역효과를 만들 수 있는가

이 부분이 단순 뉴스 요약과 market-memo의 차이입니다.

## 6. 핵심 근거와 숫자

숫자를 많이 넣는 것이 아니라 논리를 검증하는 숫자를 넣습니다.

좋은 숫자:
- 현재 주문량 대비 생산능력
- 수주잔고와 생산 슬롯
- 납기
- 증설 규모
- 가격 변화
- 매출·수주·가동률
- 실제 계약 수

중요 숫자는 가능하면 원자료를 확인합니다. 기관 전망은 '전망'이라는 점을 명시합니다.

## 7. 반론과 다른 시나리오

전망이 있는 문서는 가능하면 반대쪽 논리도 확인합니다.

예:

~~~text
기본 시나리오: AI 전력수요 지속 → 증설 물량도 흡수
반대 시나리오: 데이터센터 착공 지연 → 공급 증가가 수요를 추월
~~~

반론을 억지로 만들 필요는 없지만, 합리적인 다른 가능성이 있으면 반드시 적습니다.

'2030년 공급과잉'처럼 미래 전망은 확정 사실과 분리합니다.

## 8. 투자 관점

투자 관점에서는 단순 관련주 목록보다 다음을 봅니다.

- 직접 수혜인가, 간접 수혜인가
- 이미 실제 계약·매출이 있는가
- 공급 부족이 기업의 가격·납기 경쟁력으로 연결되는가
- 경쟁사 증설이 향후 마진을 압박할 수 있는가
- 단발성 장비 판매인지 장기 서비스 매출까지 이어지는가
- 현재 기대가 이미 주가에 상당 부분 반영됐는가

주가 원인은 뉴스 하나로 단정하지 않습니다.

## 9. 시간순 흐름

복잡한 사건은 연도 또는 날짜 순서로 정리합니다.

예:

~~~text
2024~2026 수요 급증
→ 2026~2028 제조사 증설
→ 2028~2030 증설 물량 본격 투입
→ 2030 이후 수요가 공급 증가를 따라가는지가 핵심
~~~

발생일, 발표일, 공시일, 보도일이 다르면 구분합니다.

## 10. 앞으로 확인할 지표

'앞으로 볼 것'은 막연하게 쓰지 않습니다.

좋은 예:
- 신규수주
- 생산 슬롯
- 납기 변화
- 가격
- 가동률
- CAPA 대비 수주잔고
- 실제 착공
- 다음 실적발표
- 정부 법안 통과 여부

이 지표가 좋아지거나 나빠질 때 기존 판단이 어떻게 바뀌는지도 설명하면 좋습니다.

## 11. 어려운 용어는 접어서 설명

본문을 읽다가 모르는 단어 때문에 흐름이 끊기지 않게 합니다.

~~~html
<details>
<summary>리드타임이란?</summary>

주문을 넣은 시점부터 실제 제품을 공급받기까지 걸리는 기간입니다.

</details>
~~~

대상:
- 영어 약어
- 산업 전문용어
- 금융·회계 용어
- 정책·법률 용어
- 기술 용어

쉬운 단어까지 모두 설명하지는 않습니다.

## 12. 분량

고정 글자 수 제한을 두지 않습니다.

대신 다음 규칙을 지킵니다.

- 상단 요약은 짧게
- 이해에 필요한 인과관계는 충분히
- 같은 설명은 한 번만
- 관련 기업 무더기 나열 금지
- 중요하지 않은 숫자 나열 금지
- 출처 내용을 그대로 길게 옮기지 않기

산업·정책처럼 구조를 알아야 하는 주제는 긴 설명을 허용합니다. 일일 시황은 같은 원칙을 짧게 적용합니다.

## 13. 사실과 해석 구분

필요한 경우 다음 라벨을 사용합니다.

- **[확정]** 공식 자료로 확인
- **[당사자 주장]** 기업·정부·관계자의 설명
- **[가능성 높음]** 복수 근거가 있으나 확정 전
- **[시장 기대]** 시장이 기대하지만 공식 확정 전
- **[추정]** 공개 사실을 바탕으로 한 분석
- **[확인되지 않음]** 검증되지 않은 주장

라벨을 남발하지 않고 중요한 불확실성에서 사용합니다.

## 14. 업데이트할 때

기존 문서를 업데이트할 때는 최신 내용을 뒤에 붙이기만 하지 않습니다.

~~~text
기존 문서 검증
→ 틀리거나 오래된 내용 수정
→ 새 사실 반영
→ 기존 논리와 충돌하는지 확인
→ 반론·추적지표 갱신
→ 중복 제거
~~~

문서가 길어져도 구조가 더 명확해졌다면 괜찮습니다. 반대로 길기만 하고 이해도가 늘지 않으면 줄입니다.

## 15. 작성 완료 체크

~~~text
[ ] 3줄 핵심으로 방향을 잡을 수 있다
[ ] 처음 보는 사람도 배경을 이해할 수 있다
[ ] 원인과 결과가 연결돼 있다
[ ] 핵심 숫자의 출처가 확인돼 있다
[ ] 전망을 사실처럼 쓰지 않았다
[ ] 반론 또는 다른 시나리오를 검토했다
[ ] 실제 기업·실적 연결을 확인했다
[ ] 앞으로 무엇을 보면 판단이 바뀌는지 적었다
[ ] 어려운 용어가 설명돼 있다
[ ] 결론과 기억할 한 문장이 있다
[ ] 같은 내용이 반복되지 않는다
~~~
